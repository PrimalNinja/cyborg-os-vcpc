CYBORG-OS-VCPC - build info
===========================

Build number: YYYYMMDD-N
  YYYYMMDD is the date the archive was built, Australia/Sydney local time (the
  maintainer's day; entries before 20261109-1 used the UTC date). N starts at 1 each day and is
  incremented by 1 on EVERY build, whether or not that build was taken (applied).
  The number counts builds, not releases.

Maintaining this file
  - On every build, add a NEW entry at the TOP of the history below (newest first).
  - The entry heading is the build number: today's date, with N one higher than
    the highest N already used for today (1 if today has no entry yet).
  - Under the heading, list that build's changes as dot points.
  - Do not edit or delete older entries - they are the history.

Packaging rule (what goes in the archive) - READ THIS BEFORE ZIPPING
  - Top folder is UPPERCASE: CYBORG-OS-VCPC.
  - INCLUDE all source AND tooling: src/ (vcpc.c, compat.h, the z80 core), Makefile,
    tools/, docs/, and build/ with the built binaries - build/vcpc (Linux, built
    with make) and build/vcpc.exe (Windows). Rebuild build/vcpc for your target
    with make.
  - EXCLUDE only scratch: any __pycache__/, temp run dirs, and the VCS .git/.
  - When in doubt, keep it. Dropping a tracked file is the error to avoid.

20261108-2
----------
- VER on a vCPC: the version a slot reads from its page zero (#0051 a word, (year - 2000) * 512 +
  month * 32 + day; #0053 the day's number - as the CPC's hypervisor puts its build-info number
  there, CyborgOS 20261108-3) is this vCPC's own build number: the Makefile passes this file's
  top entry as COS_BUILD, install() writes the three bytes (src/vcpc.c cos_version). So add the
  entry here, then make - VER then shows "CyborgOS 20261108.002 (vCPC)". A build without the
  define shows 20000000.000. tools/regress/vcpctest.sh checks VER's shape (20 tests).
- build/vcpc rebuilt (Linux x86-64); build/vcpc.exe is 20261105-4's (no VER bytes in it:
  rebuild for Windows with make CC=x86_64-w64-mingw32-gcc).
